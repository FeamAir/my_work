Источник правды по произношению — `canon/glossary.md` (v0.4), поле `say`; ударный слог записан ЗАГЛАВНЫМИ. Субтитры и экранный текст используют `term`. Глоссарий правит только хранитель канона. Отсюда в канон идут только предложения — через отчёт.

## 2. Формат пробы

### 2.1. Голоса и модели
- **Голоса:** NARR-01 (рассказчик), V-01 Pell (акцент Низов), V-08 Ursel (акцент Ступеней). Для приоритета 1 и строк рассказчика — все три голоса. Для остального — голос того, кто произносит слово в E1, плюс NARR-01.
- **Модели:** `eleven_multilingual_v2`, `eleven_v3`, `eleven_v4` — те же три плеча, что и в A/B (`emotion_markup.md` §6). Произношение — один из критериев выбора модели.
- **Дубли:** 2 на комбинацию. Если дубли расходятся — 3-й.

### 2.2. Несущие фразы
Каждое имя проверяется в трёх позициях: в начале фразы, в середине и в конце (на понижении интонации). Для этого один текст на термин:

```text
<TERM>. That is how the name is written. They spoke of <TERM> in the hall, and the clerk wrote down <TERM>.
```

Пример: `Ashare. That is how the name is written. They spoke of Ashare in the hall, and the clerk wrote down Ashare.`
Плюс **боевая строка** — та, где слово звучит в E1, дословно (для рассказчика — только фиксированные строки).

Тексты пробы собираются в один файл запроса на голос и модель (≈ 3 500–5 000 символов, в лимитах моделей). Нарезка — по паузам.

### 2.3. Объём (оценка)
Приоритет 1: 3 термина × 3 голоса × 3 модели × 2 дубля × ~110 симв. ≈ 6 000 символов.
Приоритеты 2–3 и омографы: ≈ 45 терминов × ~1,5 голоса × 3 модели × 2 дубля × ~110 симв. ≈ 45 000 символов.
Чтобы не тратить лишнего, приоритеты 2–3 гоняем только на **двух** моделях, прошедших первый отсев A/B. Тогда ≈ 30 000 символов. Итого ≈ 36 000 символов TTS. Запуск — только после разрешения директора.

### 2.4. Лист оценки (`studio/sound/probe/pron_results.csv`, создаётся на пробе)

| Поле | Значение |
|---|---|
| term_id | TERM-NNNN |
| voice | V-01 / V-08 / NARR-01 … |
| model | v2 / v3 / v4 |
| take | 1 / 2 / 3 |
| position | start / mid / end / line |
| stress_ok | да / нет |
| vowels_ok | да / нет |
| verdict | ✔ как в `say` · ≈ допустимо (указать, как прозвучало) · ✘ неверно |
| heard_as | как услышали (свободная запись) |
| fix_step | 0–5 (см. §3) |
| file | имя файла дубля |

Оценивают двое: звукорежиссёр и директор (или любой член команды, не читавший `say`), вслепую по тексту. Термин **принят**, если ✔ или ≈ во всех позициях у обоих оценщиков в двух дублях из двух.

## 3. Если движок читает неверно — лестница исправлений

Идём по шагам и останавливаемся на первом сработавшем. Каждый шаг записывается в `fix_step`.

| Шаг | Что делаем | Где хранится | Ограничения |
|---|---|---|---|
| 0 | Пишем как есть (`term`) | — | — |
| 1 | Контекст и пунктуация: запятая или пауза перед именем, имя не в самом конце длинной фразы | `tts_text` строки | для рассказчика **запрещено**: его текст не меняется |
| 2 | **Словарь произношений** (pronunciation dictionary, alias-правило): `Ashare` → вариант написания. Пробуем 2–3 варианта: `ah-SHAH-reh`, `Ah Shahreh`, `Ashahray`. Словарь подключается к запросу, текст реплики и субтитры не меняются | `studio/sound/lexicon/hollowstone_en.pls` (ведёт звукорежиссёр; содержимое = утверждённые `say` хранителя) | поиск в словаре чувствителен к регистру, срабатывает только первое совпадение. Длинные формы ставим раньше коротких («House Ashare» раньше «Ashare»). Словарь общий для всех голосов |
| 3 | **IPA** (только `eleven_v4`: понимает IPA в косых чертах прямо в тексте, `/ɑˈʃɑːrɛ/`) | `tts_text` строки, IPA — из столбца §1 | субтитры берут `term`, `tts_text` в них не попадает. Для рассказчика допустимо: слова те же, меняется только подсказка произношения. Фиксировать в журнале строки |
| 4 | Другая модель **для этого голоса** — только в рамках выбора модели A/B, не на одну реплику | — | смешивать модели внутри одного голоса нельзя |
| 5 | Запрос хранителю канона через директора: правка `say` или (в крайнем случае) написания `term` | отчёт звукорежиссёра | правило глоссария №4: написание должно читаться TTS по одному `say` |

Фонемные теги `<phoneme>` по текущей документации работают только с `eleven_flash_v2`. Для наших моделей не применяем.

**Омограф «read» в строке рассказчика:** сначала шаг 0 (контекст «was read» обычно даёт /rɛd/). Если не вышло — шаг 3 (IPA /rɛd/ в `tts_text`, на v4). Если выбрана не v4 — генерируем 3 дубля и берём верный. Alias «read → red» в словаре **нельзя**: он сломает «I only read it» у Lucan. Текст строки не меняется ни при каких условиях.

## 4. Что сдаём после пробы

1. `pron_results.csv` (все оценки).
2. Отчёт хранителю (через директора): какие `say` подтверждены; какие нужно поправить, с вариантом, который сработал; предложение заполнить `ipa` для приоритета 1; вопрос echo-chip / echo-shard.
3. Словарь `hollowstone_en.pls` v1 — только из подтверждённых записей.
4. На будущее: такие же словари `hollowstone_es.pls`, `_pt.pls`, `_ru.pls` для дубляжа. Имена **не переводятся**, но испанский или русский голос прочтёт «Ione» по-своему, поэтому проба по этому же списку повторяется на каждом языке (`dubbing_ready.md` §6).
